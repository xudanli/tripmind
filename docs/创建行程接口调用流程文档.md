# 创建行程接口调用流程文档

本文档详细说明创建行程时会调用的所有接口，以及性能优化建议。

## 一、创建行程完整流程

### 流程概览

```
用户提交表单
  ↓
1. 生成行程 (POST /api/v1/journeys/generate) ⏱️ 慢（LLM 调用）
  ↓
2. 创建行程 (POST /api/v1/journeys/from-frontend-data) ⏱️ 中等
  ↓
3. 更新行程 (PATCH /api/v1/journeys/{journeyId}/from-frontend-data) ⏱️ 中等
  ↓
4. 异步获取位置信息 (POST /api/location/generate-batch-async) ⏱️ 慢（后台执行）
  ↓
5. 跳转到详情页
```

## 二、详细接口调用说明

### 1. 生成行程接口 ⏱️ **最慢**

**接口**：`POST /api/v1/journeys/generate`  
**文件**：`src/services/itineraryAPI.ts:420`  
**调用位置**：`src/stores/travel.ts:504`

**请求参数**：
```typescript
{
  destination: string        // 目的地
  days: number              // 天数
  startDate: string         // 开始日期
  preferences?: {           // 用户偏好
    interests?: string[]
    budget?: "low" | "medium" | "high"
    travelStyle?: "relaxed" | "moderate" | "intensive"
  }
  mode?: 'planner' | 'inspiration'
}
```

**响应数据**：
```typescript
{
  success: boolean
  data: {
    destination: string
    days: Array<{
      id: string
      day: number
      date: string
      timeSlots: Array<{
        time: string
        title: string
        type: string
        coordinates?: { lat: number; lng: number }
        // ...
      }>
    }>
    totalCost: number
    summary: string
    practicalInfo?: { ... }
  }
}
```

**性能特点**：
- ⏱️ **最慢的接口**（通常 10-30 秒）
- 需要调用 LLM（DeepSeek/OpenAI）生成行程
- 生成内容包括：活动安排、费用估算、实用信息等
- **优化建议**：无法避免，但可以显示进度提示

**当前优化**：
- ✅ 已设置 `enrichWithLocationInfo: false`，生成时不获取位置信息
- ✅ 有进度回调 `onProgress`，可以显示加载状态

---

### 2. 创建行程接口 ⏱️ **中等**

**接口**：`POST /api/v1/journeys/from-frontend-data`  
**文件**：`src/services/itineraryAPI.ts:3120`  
**调用位置**：`src/views/PlannerView.vue:361`

**请求参数**：
```typescript
{
  itineraryData: {
    destination: string
    duration: number
    days: Array<{
      day: number
      date: string
      timeSlots: Array<{ ... }>
    }>
    totalCost: number
    summary: string
    title: string
    preferences?: any
    practicalInfo?: any
  }
  startDate: string
}
```

**响应数据**：
```typescript
{
  success: boolean
  data: {
    id: string              // 行程ID
    destination: string
    daysCount: number
    days: Array<{ ... }>
  }
}
```

**性能特点**：
- ⏱️ **中等速度**（通常 1-3 秒）
- 将前端数据格式转换为后端格式并保存到数据库
- 包含数据验证和清理逻辑
- **优化建议**：可以优化数据清理逻辑，减少处理时间

**当前优化**：
- ✅ 数据清理逻辑已优化（移除空字段）
- ✅ 支持批量保存 days 和 timeSlots

---

### 4. 异步获取位置信息 ⏱️ **慢（后台执行）**

## 三、性能瓶颈分析

### 主要瓶颈

1. **生成行程接口**（10-30 秒）
   - 原因：LLM 调用，无法避免
   - 优化：显示进度提示，改善用户体验

2. **创建 + 更新接口**（2-6 秒）
   - 原因：两次数据库操作（创建 + 更新）
   - 优化：合并为一次操作，或移除更新步骤

3. **位置信息获取**（5-20 秒）
   - 原因：批量调用外部 API
   - 优化：已改为异步，不阻塞创建流程

### 总耗时估算

**优化前流程**：
- 生成行程：10-30 秒
- 创建行程：1-3 秒
- 更新行程：1-3 秒
- **总计**：12-36 秒

**优化后流程**（已移除更新步骤）：
- 生成行程：10-30 秒
- 创建行程：1-3 秒（包含完整数据）
- **总计**：11-33 秒（✅ 节省 1-3 秒）

## 四、性能优化建议

### 1. 立即优化（高优先级）

#### ✅ 移除冗余的更新步骤（已完成）

**问题**：创建行程后立即更新，可能是冗余操作

**位置**：`src/views/PlannerView.vue:334-410`

**优化方案**：
```typescript
// 优化前：两次请求
const baseJourney = await createJourneyFromFrontendData(createRequest)
backendItinerary = await updateJourneyFromFrontendData(backendItineraryId, updateRequest)

// 优化后：合并为一次请求
const finalRequest = {
  ...createRequest,
  itineraryData: {
    ...createRequest.itineraryData,
    ...updateRequest.itineraryData  // 合并所有数据
  }
}
backendItinerary = await createJourneyFromFrontendData(finalRequest)
```

**优化效果**：✅ 节省 1-3 秒

---

#### ✅ 优化数据清理逻辑

**问题**：创建前进行大量数据清理和验证

**位置**：`src/services/itineraryAPI.ts:3200-3265`

**建议**：
- 将数据清理逻辑移到后端
- 前端只做基本验证
- 减少前端处理时间

**预期效果**：节省 0.5-1 秒

---

### 2. 中期优化（中优先级）

**预期效果**：可能节省 1-2 秒（取决于后端处理）
